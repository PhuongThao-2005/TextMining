\section{Implementation and Experimental Setup}
\label{sec:implementation-setup}

This section states the controls and scoring rules needed to interpret the
ablations in Section~\ref{sec:ablation-study}. The benchmark and corpus are
shared where possible, but the five reported analyses are grouped into four
run families and are not one factorial experiment: candidate pools, context
construction, output limits, and latency accounting differ. A result is
therefore compared only with its paired control inside the same family.

\subsection{Pipeline and Frozen Artifacts}
\label{sec:software-architecture}

The evaluated pipeline consists of five stages: (1) query embedding with \texttt{intfloat/multilingual-e5-large};
(2) dense FAISS retrieval and, where enabled, tokenized BM25 retrieval;
(3) RRF fusion, graph-based context selection, or cross-encoder reranking;
(4) serialization of retained chunks into a grounded prompt;
and (5) answer generation followed by post-hoc evaluation.

All reported analyses operate on frozen artifacts rather than rerunning models.
Each run is associated with a manifest identifying the run configuration, 
corpus snapshot, benchmark version, model checkpoint or revision, random seed, and code revision.
Checksums for the benchmark and major corpus or index artifacts are retained where available 
so that the evaluated inputs can be distinguished from later repository or dataset updates.
Runtime metadata such as execution timestamp, software environment, and hardware configuration is recorded with the run artifacts when available; detailed manifest fields are listed in Appendix~F.

The analysis reads saved manifests, per-question predictions, retrieved context identifiers, aggregate metrics, latency records, and error logs.
Every primary comparison is aligned by \texttt{qa\_id}. A row is considered valid when it has status \texttt{success}, \texttt{completed}, or \texttt{ok}, has no saved error, and is not marked \texttt{failed}, \texttt{error}, or \texttt{skipped}; older artifacts without a status field fall back to the presence of a saved prediction.
The same identifier links the question category, answer type, reference answer, gold evidence, ordered retrieved context, output diagnostics, and latency record.
Reported paired effects are therefore computed only over question IDs satisfying the validity requirements of both compared conditions.

The completed experiments address five research questions:
\begin{enumerate}
    \item Does document and provision metadata improve exact evidence
    retrieval or document-level coverage?
    \item Does dense--sparse hybrid retrieval improve coverage or rank over
    dense retrieval alone?
    \item Does the current G-LRAG graph policy improve evidence coverage or
    downstream behavior under a ten-chunk context budget?
    \item Which reranker best trades ranking quality against cost when the
    candidate pool is fixed?
    \item Does an explicit chain-of-thought prompt improve observable answer
    behavior when the retrieved context is fixed?
\end{enumerate}

\subsection{Indexes, Graph, and Runtime Settings}
\label{sec:build-process}

The dense/hybrid/graph experiment uses a FAISS index with 1,513,376 chunk
vectors and a graph over the same chunk identifiers. The hybrid branch
searches ten independently built BM25 shards, each with shard-local IDF and
average-document-length statistics; shard candidates are merged by BM25 score
before RRF. Dense and hybrid retrieval use a 50-result search budget, broad
filtering, and a final context of ten chunks; RRF uses $k=60$ when BM25 is
enabled. Graph variants take five seed chunks within their parent provisions,
use \texttt{max\_hop=1}, replace the baseline context, and retain at most ten
graph-context chunks. This family uses broad validity filtering without a
query-time validity overlay or reranking. The associated generation artifacts
use \texttt{gpt-4o-mini}.

The reranker family fixes a 30-chunk RRF candidate pool ($C_{30}$) and a
ten-chunk final context ($T_{10}$). It compares no reranking, RRF-only,
mMiniLM, Qwen3, BGE, and Jina. The primary generator study compares
GPT-4o-mini Base and CoT with the saved top-10 context fixed by question.
The metadata study changes only the indexed string from chunk body to
header-plus-chunk text; encoder, FAISS, top-$k=10$, generator, prompt, seed,
corpus, and benchmark remain fixed.

\subsection{Benchmark and Metrics}
\label{sec:evaluation-metrics}

The benchmark contains 500 questions: 400 answerable questions with gold chunk identifiers
and 100 unanswerable questions. Retrieval metrics are computed only on the 400 answerable questions.
Let $G_i$ denote the gold chunk set for question $i$, and let $R_{i,k}$ denote the ordered set of retrieved chunks up to rank $k$.
Recall and hit rate are defined as

\begin{equation}
\begin{aligned}
\mathrm{Recall@}k_i
&=
\frac{|G_i \cap R_{i,k}|}{|G_i|},\\
\mathrm{Hit@}k_i
&=
\mathbb{1}[G_i \cap R_{i,k} \neq \varnothing].
\end{aligned}
\end{equation}

Let $r_i$ be the rank of the first retrieved gold chunk, with $r_i=\infty$
when no gold chunk is retrieved. Truncated reciprocal rank is

\begin{equation}
\mathrm{MRR@}k_i =
\begin{cases}
1/r_i, & r_i \leq k,\\
0, & r_i > k.
\end{cases}
\end{equation}

For nDCG, retrieved chunks use binary relevance,
$\mathrm{rel}_{i,j}=1$ when the chunk at rank $j$ belongs to $G_i$ and $0$ otherwise:
\begin{equation}
\frac{\mathrm{DCG@}k_i}{\mathrm{IDCG@}k_i},
\end{equation}

where $\mathrm{IDCG@}k_i$ is the maximum possible DCG obtained by placing up to $\min(|G_i|,k)$ gold chunks at the highest ranks.

Candidate Recall@30 and Candidate Hit@30 measure whether gold evidence is present in the shared 30-candidate pool used by the reranker family. Because this pool is fixed before reranking, these metrics define the maximum evidence coverage available to every reranker condition.

For graph analyses that may return fewer than $k$ chunks, identity-level precision measures the fraction of returned chunks whose mapped document or provision identifier belongs to the corresponding gold identity set. When no chunk is returned, identity precision is defined as zero.

For a normalized prediction $y_i$ and reference answer $r_i$, Exact Match is

\begin{equation}
\mathrm{EM}_i =
\begin{cases}
1, & y_i = r_i,\\
0, & y_i \neq r_i.
\end{cases}
\end{equation}

The lexical evaluator normalizes text with Unicode NFC, lowercasing, punctuation-to-space replacement, and whitespace collapse. Token F1 uses token overlap $O_i$ and prediction/reference token counts $L_i^y$ and $L_i^r$ when both token lists are non-empty:

\begin{equation}
P_i=\frac{O_i}{L_i^y},
\qquad
R_i=\frac{O_i}{L_i^r},
\qquad
F_{1,i}=\frac{2P_iR_i}{P_i+R_i}.
\end{equation}

When both prediction and reference tokenize to empty strings, Token F1 and ROUGE-L return 1.0; when exactly one side is empty, they return 0.0. ROUGE-L otherwise uses the same F-score structure with the token-level longest common subsequence in place of direct token overlap. Exact Match, Token F1, and ROUGE-L are computed only on valid answerable outputs and are treated as lexical-overlap diagnostics rather than measures of legal correctness.

Unanswerable behavior is reported separately from retrieval quality. For the retrieval/graph family, the \textit{fallback-marker rate} is the fraction of the 100 unanswerable outputs containing the expected Vietnamese fallback phrase, ``Không có đủ thông tin trong ngữ cảnh được cung cấp.'' This is a template-based abstention diagnostic rather than semantic proof that the response correctly recognized insufficient evidence. The 500-question answerability-decision diagnostic used in other run families is reported separately.

Citation presence is the fraction of valid answerable outputs containing at least one parsed citation marker. Structural citation coverage is the fraction of factual sentences identified by the saved output parser that contain at least one citation marker. The post-hoc analysis averages this metric only over valid answerable rows with a non-null saved \texttt{structural\_citation\_coverage} value; rows with no scored factual sentences save this value as null and are excluded from that denominator. These citation metrics measure observable output structure only and do not test whether a cited source entails, fully supports, or legally justifies the associated claim.

Completion rate is the number of valid completed rows divided by the number of scheduled rows. Latency is reported in seconds using saved mean, p50, and p95 values where available. The hybrid retrieval totals include an amortized BM25 preprocessing cost of 26.990 seconds per query, obtained from 13,495 seconds of batch computation over 500 questions; this value is therefore not a direct online request-latency measurement. Reranker experiments use cached BM25 candidates and likewise do not represent full online sparse-retrieval latency.

Metric preprocessing is evaluator-specific. Retrieval/graph evaluations lowercase text and collapse whitespace while preserving punctuation, whereas the generator-reasoning lexical evaluator applies Unicode NFC normalization and replaces punctuation with spaces before tokenization. Scores are compared only within the evaluator and run family that produced them.

\subsection{Pairing, Uncertainty, and Claim Boundaries}
\label{sec:experimental-protocol}

Headline effects are paired by \texttt{qa\_id}. Retrieval deltas use the
shared answerable intersection; scheduled-denominator answerability
diagnostics retain all 500 cases. Percentile paired-bootstrap confidence
intervals use 10,000 resamples (seed 42) for headline metadata,
dense/hybrid, reranker, and GPT comparisons, and 2,000 resamples for the
smaller reranker slices. An interval crossing zero is reported as
inconclusive rather than as evidence of an effect. Exact Match in the primary
GPT pair also uses an exact McNemar test.

The primary GPT-4o-mini Base/CoT runs complete 500/500 cases and have
identical ordered top-10 chunk-ID sequences for every question. DeepSeek,
GLM, and Qwen prompt pairs are descriptive checks: four DeepSeek cases have
different context order, and the Qwen manifests differ in code snapshot,
timeouts, or retry limits. No prompt effect is pooled across models.

Output limits are family-specific: the retrieval/graph runs set no explicit
client-side output-token cap, while the fixed-context generator-reasoning
comparison uses a 1,024-token limit. The graph policy is consequently tested
as a full context-selection change (seed selection plus expansion), not as an
isolated add-on to an otherwise fixed top-10 list.

The artifacts contain no blinded legal-correctness labels, claim-level
faithfulness labels, validated semantic judge, preferred
answer/clarify/refuse labels, raw chain-of-thought, or reasoning-token
accounting. Thus, no result is interpreted as proof of legal correctness,
legal safety, citation entailment, or faithful reasoning merely because it
improves a lexical, rank, citation-format, refusal-format, or latency metric.

\subsubsection{Reproducibility ledger}

Each condition is accompanied by a manifest, per-question output records,
metric summary, and latency file. Derived analyses are versioned with their
source artifacts under \url{ablation_study/} and \url{ablation_work/}; the
reranker candidate reconstruction and paired analysis are in
\url{ablation_work/reranker_choices/analyze_reranker_metrics.py}, while the
generator post-hoc report is in
\url{ablation_study/e2e_LLM_reasoning/results/report.md}. The report reads
these frozen files and does not call a model during analysis.
