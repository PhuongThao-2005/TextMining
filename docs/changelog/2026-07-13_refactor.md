# Changelog — Facade, Context Integration & Refactoring

## Summary
Integrated the Knowledge Graph query planning layer with the vector search engine. Exposed unified public APIs via `KnowledgeGraphFacade` and refactored linter dependencies using unified configuration settings.

## Motivation
Downstream search tasks require a simple integration surface. The facade orchestrates the sub-services, and the context builder constructs whitelists to filter search operations cleanly, keeping database adapters decoupled from vector logic.

## Files Changed
* **Created:**
  - `src/knowledge_graph/facade.py` (Unified public integration API boundary)
  - `src/knowledge_graph/context.py` (Orchestrates constraints and overlays)
  - `src/knowledge_graph/context_schema.py` (Filter and Evidence bundle definitions)
  - `pyproject.toml` (Unified python configuration root)
  - `scripts/verify_kg.py` (End-to-end integration verification script)
* **Modified:**
  - `src/retrieval/retriever.py` (Updated to accept and apply `GraphGuidedFilter` whitelists)

## Major Implementation Details
* **Facade Orchestration:** `KnowledgeGraphFacade` wraps loader, builder, traverser, overlay, and context filters to expose a single orchestrator boundary.
* **Graph-Guided Filtering:** `ContextBuilder` applies query constraints (such as sector, scope, issuing authority) to traversal sets.
* **Empty Whitelist Warning:** Correctly surfaces warnings when candidate whitelists are empty, avoiding silent degradations.
* **Retriever Integration:** Upgraded `VectorRetriever` to intersect search payloads with guided whitelists.
* **Unified Tooling Config:** Added `pyproject.toml` specifying the `src/` folder for `pytest`, `pyright`, and `pyrefly` packages to prevent "missing-import" linter issues.
